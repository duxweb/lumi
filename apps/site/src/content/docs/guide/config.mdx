CDN 版后台只读一个 `config.json`，它在 HTML 里由 `data-config` 指定：

```html
<!-- data-config 指向这个后台的配置文件 -->
<script
  type="module"
  src="https://cdn.jsdelivr.net/npm/@duxweb/lumi-admin@0.1/dist/base/lumi-admin.js"
  data-config="/config.json"
></script>
```

`config.json` 里的相对地址（`data` 的 `url`、`manifest`、`theme`、`modules`、语言文件）都相对于 `config.json` 本身。

配置也可以直接写在页面里，不单独放文件：`window.LumiAdminConfig = { … }`，或 `<script type="application/json" id="lumi-admin-config">`，由后端渲染 HTML 时输出。这时没有配置文件可以参照，地址请写成以 `/` 开头的路径或完整网址。写法见 [CDN 版的扩展](/guide/modules/#不单独放文件)。

## 结构

配置分四块，跟 Lumi 的 provider 一一对应：

| 节点 | 是什么 | 对应 |
| --- | --- | --- |
| `data` | 后端地址 | DataProvider |
| `auth` | 登录方式和接口 | AuthProvider |
| `access` | 权限串的规则 | AccessProvider |
| `panels` | 后台入口：路径、菜单、登录页，用哪个 `data`、`auth`、`access` | 一个 `createAdmin` |

这四块的写法完全一样：写成**对象**表示只有一个（名字是 `default`，也可以自己写 `name`），写成**数组**表示有多个（每项必须写 `name`，不能重名）。引用时都写名字：panel 的 `data`、`auth`、`access`，auth 的 `data`，页面里的 `dataProviderName`。

## 一个后台

最常见的情况，每块都只有一个：

```jsonc
{
  // 后端：数据请求、登录、上传都发到这里
  "data": {
    // API 根地址，资源 orders 就请求 https://api.example.com/orders
    "url": "https://api.example.com",
    // 可选：后端推送变化的 SSE 地址，收到后列表自动刷新
    "live": "/events"
  },
  // 登录：怎么登录、凭证存哪
  "auth": {
    // token 存在 localStorage 的键名
    "tokenKey": "shop_token",
    // 登录相关接口，相对于 data.url；不写就是默认的 /login、/me
    "endpoints": {
      "login": "/login",
      "me": "/me",
      // 请求返回 401 时先调它续期，成功就自动重发
      "refresh": "/refresh"
    }
  },
  // 权限串的格式：system/users 加 delete 拼成 system:users:delete
  "access": { "separator": ":" },
  // 后台入口：菜单和登录页
  "panels": {
    // 菜单和路由，可以是静态文件，也可以是按用户返回的接口
    "manifest": "/manifest.json",
    // 登录页上的文字
    "login": { "heroTitle": "示例商城后台" }
  },
  // 界面语言
  "i18n": { "locale": "zh-CN" },
  // 可选：自定义组件、动作的扩展脚本
  "modules": ["/ext/order-summary.js"]
}
```

只有 `data` 和 `panels.manifest` 必填。`auth` 和 `access` 不写时用默认约定，见 [数据接口](/guide/backend/)。

## 多个后台

同一次部署提供多个后台，比如运营后台和商家后台，各自有自己的路径、菜单和登录：

```jsonc
{
  // 写成数组就是多个后端，用 name 区分
  "data": [
    // 主后端。panel 没指定 data 时用第一个，所以两个后台的页面默认都请求它
    { "name": "main", "url": "https://api.example.com", "live": "/events" },
    // 公共内容后端：auth: false 不带登录凭证，它返回 401 也不会让用户退出
    // 页面里写 "dataProviderName": "cms" 就从这里取数据
    { "name": "cms", "url": "https://cms.example.com/api", "auth": false }
  ],
  // 两套登录：员工和商家是两批账号
  "auth": [
    {
      // 员工登录，用 token；token 存在 lumi_staff_token，不和商家的冲突
      "name": "staff",
      "endpoints": { "login": "/admin/login", "me": "/admin/me" }
    },
    {
      // 商家登录，靠后端的会话 cookie，浏览器里不存 token
      "name": "merchant",
      "mode": "cookie",
      "endpoints": { "login": "/merchant/login" }
    }
  ],
  // 一份权限规则，两个后台共用：权限串写成 system.users.delete
  "access": { "separator": "." },
  // 两个后台入口，地址决定打开哪个
  "panels": [
    {
      // 运营后台：/admin 下的地址都进这里
      "name": "admin",
      "path": "/admin",
      // 它自己的菜单
      "manifest": "/admin/manifest.json",
      // 用员工账号登录
      "auth": "staff"
    },
    {
      // 商家后台：/merchant 下的地址都进这里
      "name": "merchant",
      "path": "/merchant",
      "manifest": "/merchant/manifest.json",
      // 用商家账号登录，和运营后台的登录互不影响
      "auth": "merchant",
      // 自己的品牌色和 logo；不写就用根上的 theme
      "theme": "/merchant/theme.json",
      // 登录页显示"商家中心"
      "login": { "title": "商家中心" }
    }
  ],
  // 打开 / 或其他不属于任何后台的地址时，进入哪个后台；不写就是第一个
  "defaultPanel": "admin"
}
```

规则：

- panel 里的 `data`、`auth`、`access` 写名字；不写时用名为 `default` 的那个，没有就用第一个。
- 每个 panel 有独立的会话和缓存。两个 panel 写同一个 `auth`，就共享同一次登录。没写 `tokenKey` 时，每个 auth 的 token 存在不同的键里，互不覆盖。
- 地址落在哪个 panel 的 `path` 下就打开哪个，最长的匹配优先；不在任何 panel 下（比如 `/`）时打开默认 panel 并跳到它的路径。
- panel 之间用普通链接跳转（如 `<a href="/merchant">`），换 panel 会重新加载。
- 页面里的 `dataProviderName` 写 `data` 的名字。不写时用当前 panel 的 `data`。

### 每个后台一个 HTML

所有 panel 默认共用一个 HTML，按地址选择。也可以每个 panel 单独一个 HTML，在脚本上用 `data-panel` 指定：

```html
<!-- merchant/index.html -->
<!-- data-panel 指定这个页面只挂载 merchant 这个 panel -->
<script
  type="module"
  src="https://cdn.jsdelivr.net/npm/@duxweb/lumi-admin@0.1/dist/base/lumi-admin.js"
  data-config="/config.json"
  data-panel="merchant"
></script>
```

两种方式用的是同一份 `config.json`。编译接入时用 `mountAdmin(config, extensions, { panel: 'merchant' })`。

## 根

| 配置 | 说明 |
| --- | --- |
| `data`（必填） | 后端，见下文。 |
| `panels`（必填） | 后台入口，见下文。 |
| `auth` | 登录方式，见下文。不写时用默认约定。 |
| `access` | 权限规则，见下文。不写时是 `资源:动作`。 |
| `defaultPanel` | 打开 `/` 或不属于任何 panel 的地址时进入哪个 panel，默认第一个。 |
| `frameOrigins` | 允许嵌入的站点，如 `["https://bi.example.com"]`，`page.iframe` 和 `Iframe` 元素都受它限制；本站总是允许。不写时所有 https 站点都可以。见 [嵌入其他网页](/guide/embed/)。 |
| `packKey` | 后端把菜单、页面、主题打包返回时用的密钥，见 [不让页面 JSON 直接可读](/guide/remote/#不让页面-json-直接可读)。不加密钥时不用写。 |
| `el` | 挂载的元素，默认 `#app`。 |
| `basename` | 整个站点不在域名根目录时的路径前缀，如 `/console`。panel 的 `path` 都在它下面。 |
| `theme` | 所有 panel 默认的主题，地址或对象，见 [主题](/guide/theme/)。 |
| `i18n` | 语言和翻译，见下文。 |
| `modules` | 扩展模块（ES 模块）的地址，在后台启动前按顺序加载，见 [扩展模块](/guide/modules/)。 |
| `cacheKey` | 本地缓存（manifest、工作区等）的命名空间，同一个域名下部署多套配置时用来区分。多个 panel 时每个 panel 在它下面各有一份。 |

## data

| 配置 | 说明 |
| --- | --- |
| `name` | 名称，数组时必填。 |
| `url`（必填） | API 根地址。数据请求、登录、上传都相对于它。 |
| `live` | 后端推送变化的 SSE 地址，相对于 `url`。收到 `resources/{资源}` 事件时，对应的列表和详情自动刷新。只对把它当作默认后端的 panel 生效：一个 panel 只连自己那个 `data` 的推送。 |
| `auth` | `false` 时不带登录凭证，它返回 401 也不会让后台退出。 |

格式和默认约定不一样的后端，在扩展模块里按名字换掉，见 [扩展模块](/guide/extend-backend/#适配自己的后端格式)；要签名或改请求头，见 [签名与改写请求](/guide/extend-backend/#签名与改写请求)。

## auth

| 配置 | 说明 |
| --- | --- |
| `name` | 名称，数组时必填。 |
| `mode` | `bearer`（默认）：token 存在浏览器，请求带 `Authorization: Bearer …`。`cookie`：靠后端的会话 cookie。 |
| `tokenKey` | bearer 模式下 token 在 `localStorage` 里的键名。 |
| `csrf` | cookie 模式下的防伪：`{ "cookie": "XSRF-TOKEN", "header": "X-XSRF-TOKEN" }`，写操作把 cookie 的值放进请求头。 |
| `data` | 登录接口相对于哪个 `data`，默认是使用它的 panel 的 `data`。 |
| `endpoints` | 接口地址，见下表。 |

| `endpoints` | 说明 |
| --- | --- |
| `login`、`logout`、`me` | 登录、退出、当前用户，默认 `/login`、`/logout`、`/me`。 |
| `refresh` | 续期接口。任何请求 401 时先调用它，成功就重发原请求。 |
| `register`、`forgotPassword`、`updatePassword` | 注册、找回密码、重置密码。填了地址，登录页才出现对应入口。 |

请求和返回的格式见 [对接后端](/guide/backend-auth/#登录)。登录方式完全不同（如 SSO）时，在扩展模块里按名字换掉，见 [扩展模块](/guide/extend-backend/#换成自己的登录)。

## access

| 配置 | 说明 |
| --- | --- |
| `name` | 名称，数组时必填。 |
| `separator` | 权限串的分隔符，`:`（默认）或 `.`。`system/users` 加 `delete` 拼成 `system:users:delete` 或 `system.users.delete`。 |
| `format` | 拼法模板，必须包含 `{resource}` 和 `{action}`，如 `{action}{separator}{resource}`。 |

匹配规则和通配写法见 [权限标识](/guide/backend-auth/#权限标识)。

## panels

| 配置 | 说明 |
| --- | --- |
| `name` | 名称，数组时必填。 |
| `manifest`（必填） | 菜单和路由：一个地址或直接内嵌的对象。地址可以是后端接口，见 [从后端加载菜单](/guide/remote/#从后端加载菜单)。 |
| `path` | 它在站点里的路径，如 `/admin`，默认 `/`。多个 panel 各占一个。 |
| `data`、`auth`、`access` | 用哪一个，写名字。 |
| `theme` | 这个 panel 的主题，不写用根上的 `theme`。 |
| `login` | 登录页的文字和选项，见下文。 |
| `pages` | 所有页面从同一个后端接口取：`{ "endpoint", "method", "data" }`，见 [一个接口返回所有页面](/guide/remote/#一个接口返回所有页面)。 |
| `manifestAuth` | `public`（默认）：不登录也能加载 manifest。`protected`：先确认已登录再加载，用于按用户返回菜单的接口。 |
| `auditLog` | 审计日志的资源名。填了以后，每次写入成功都会记录一条。 |
| `menuBadges` | 菜单项旁边的数字或标签，按路由的 `name`：`{ "orders": { "label": 3, "tone": "warning" } }`。 |
| `shellStorageKey` | 外壳在浏览器里保存内容的命名空间：读者的偏好（侧栏折叠等）、打开的标签页和选的语言。默认按 manifest 的 `app.id` 区分，多个 panel 时每个 panel 一份。 |

### login

都是可选的，不写时用默认文字。

| 配置 | 说明 |
| --- | --- |
| `title`、`subtitle`、`badge` | 产品名、"欢迎回来"下面的一行、标题上方的小标签。 |
| `heroTitle`、`heroHighlight`、`heroDescription` | 表单旁边的大标题、标题里用品牌色显示的部分、标题下的说明。 |
| `features` | 标题下的要点：`[{ "icon", "title", "description" }]`，`[]` 表示不显示。 |
| `help` | 右上角的帮助链接：`{ "label", "linkLabel", "href" }`。 |
| `register` | `false` 隐藏"创建账号"。 |
| `assignedNote` | 没有注册入口时表单下的说明，例如"账号由管理员分配"。 |
| `forgotPassword` | `false` 隐藏"忘记密码"；`{ "href" }` 打开自己的页面；`{ "message" }` 改提示文字。 |
| `remember` | 是否显示"记住我"，默认显示。 |
| `links` | 卡片下方的链接：`[{ "label", "href" }]`。 |
| `copyright` | 版权文字，默认 `© 年份 产品名`。 |
| `demo` | 演示账号 `{ "username", "password" }`，会出现一个一键填入的提示。正式环境不要写。 |

## i18n

所有 panel 共用。

| 配置 | 说明 |
| --- | --- |
| `locale`（必填） | 默认语言，如 `zh-CN`。 |
| `fallbackLocale` | 当前语言缺词时用的语言。 |
| `translations` | 所有页面共用的翻译，按语言写：一个 JSON 文件的地址，或直接写对象，会合并到 Lumi 自带的翻译上。页面自己的文字写在页面的 `translations` 里，见 [页面自己的翻译](/guide/i18n/#页面自己的翻译)。 |
| `format` | 金额和时间：`currency`（如 `CNY`）、`currencyUnit`（`major` 元 / `minor` 分）、`timeZone`（如 `Asia/Shanghai`）、`dateTimeInput`（`iso-utc`）。四项要一起写。 |
