# @duxweb/lumi

## 0.1.1

### Patch Changes

- e0e8013: Share session identity across derived contexts and guard writes, imports, optimistic rollback, placeholder rows and remote page caches across account or tenant changes. Prevent signed HTTP redirects from forwarding custom credentials and reject nested mutating agent UI actions.

  Unify CRUD parameter mapping, preserve JSON delete values, validate native action parameters and required record IDs, and reuse provider URL resolution for agent requests. Keep list and aggregate refreshes consistent and reset pagination when filters change.

  Separate Admin document loading and Avatar primitives, and reduce redundant test loading, fixed waits and duplicate accessibility scans while preserving integration and visual coverage.

## 0.1.0

### Minor Changes

- The default REST convention writes filter operators in brackets and sorting as one parameter: `total[gte]=100`, `status[in][]=paid`, `sort=-createdAt,name` (was `total__gte=100`, `status__in[]=paid`, `sort[]=createdAt:desc`). `eq` stays the plain field, and paging is unchanged.
- While the front end runs an agent reply's tool calls the session stays `streaming`: another message is refused until they answer, a call that answers after the conversation was switched or stopped changes nothing, and a decision taken meanwhile never runs a call twice. `stop()` ends running client calls with the reply.
- `useForm` callbacks kept from before the record changed (an upload finishing, a save going on after an await) no longer pull the form back: a late `setValues` is ignored and a late `submit` is refused.
- A list no longer keeps the previous tenant's rows on screen when the tenant changes while another page is loading.
- `useAgentChat` keeps an unnamed conversation when only its surroundings change (context, resource), instead of emptying it.
- `useTable({ syncWithLocation })` hands other query parameters back as it read them, repeated keys included.
- Signing in or out reopens the live event stream, which was signed for the previous reader; the loader drops expired entries of other keys instead of keeping them for the page's life.
- Packed documents. A server may answer a page, manifest or theme as `{ "packed": "…" }` (the JSON text, raw-deflated, optionally masked with a key, as base64) so its text does not show in the network panel; loaders unpack it before validating and caching. `createSpecLoader` and `createJsonLoader` take `packKey`; `packDocument`, `unpackDocument` and `isPackedDocument` are exported from the root and `/catalog`. It hides a document from a casual look only.
- Direct-to-storage uploads (S3, OSS, COS, R2, MinIO). `upload.sign: { url, data, complete }` asks the backend for an `UploadTicket` (`url`, `method`, `headers`, `fields`, `fileUrl`), sends the file straight to the storage with progress and cancel, never with the reader's credentials, and optionally tells `complete`. `Upload` and `ImageGrid` take it in their `upload` prop. `uploadFiles` and the new `sendFile` move to the framework-free core.
- Exports and imports the backend performs. `exportList` and `useExport` take `url` (and `method`): the endpoint is sent the filters, sorters, columns and format and answers the file as a stream, in any format, saved under the server's file name with byte progress. `importList` and `useImport` take `url`: the chosen file is uploaded as it is with upload progress and the answer `{ total, succeeded, failed, errors }` is the result. `HttpClient.download` returns the unread response; `TransferHost` gains `pickFile` and saves a `TransferDownload`.
- Credentials stay with their backend. An `HttpClient` signs, adds the tenant, default headers and hooks, refreshes and signs out only for its `baseUrl`, the page's own site and the new `trustedOrigins`; a full URL to any other site is sent plain, so a page that names a foreign address in `request` or `Query` no longer carries the reader's token there. `dataProviderHttp` gives the client that reaches a provider's backend.
- `validateDocument` checks props and action params whose own keys look like an expression (`$state`…) instead of skipping them, and reports a component or action named `constructor`, `toString` or `__proto__` as unknown instead of throwing.
- A page reloaded with new `translations` keeps working: its actions write results and `submitForm` saves, where they used to go quiet after the reload.
- `useForm` fills the form with a record that loads after the first render when the page declared state at `valuesPath`, unless the reader already edited it.
- `useTable` keeps following its rows when the aggregate request fails, instead of staying on the last snapshot; the aggregate is then undefined.
- An agent tool call waiting for the reader's approval stays open when the reply ends, instead of showing as failed.
- Exports no longer stop early: a backend that caps the page size is read to its total, and one that sends no `meta.total` is read until a short page.
- `createSimpleDataProvider` has no `createMany` any more (it only looped over `create`), so an import with `batchSize` reports each row truly; `getMany` with no ids answers no records without a request; an empty, `.` or `..` id is refused before any request.
- `createSimpleAuthProvider` ties `me` and `refresh` answers to the session that asked: a late refusal no longer signs out a new login, a late answer no longer puts the previous reader's identity under the new token, and a refresh finishing after sign-out stores nothing. Field checks follow `permission.format` wherever it puts the resource.
- A request whose 2xx body breaks off fails instead of answering an empty success; a query is appended with `&` to a path that already has one.
- `createSseLiveProvider` stays open through keep-alive frames that are not JSON and a listener that throws, backs off when the stream keeps dropping without an event, and `publish` fails on a refusal.
- CSV import reads back formula-guarded cells as they were written, a blank number as null, and keeps text that is not a number instead of sending NaN.
- `createJsonSchemaValidator` reuses compiled rules by content, so a form whose rules carry `$id` can be submitted twice; a `contains` rule without an upper bound reads "at least {min}" (`lumi.validation.contains_min`).
- `formatDateTime` accepts up to nine fractional digits, as Go writes a time.
- Field error paths are dotted (`items.0.sku`), as forms always read them; the `HttpFieldError` doc said slashes.
- English and Chinese text for `lumi.iframe.blocked`.
- One word for translated text: `createI18nProvider({ translations })` replaces `messages`, `extendI18nProvider(provider, translations)` takes the same shape, and the types are `I18nTranslations` (per locale) and `I18nTranslationTable` (one locale), replacing `I18nMessageCatalog` and `I18nMessages`; `PageTranslations` is `I18nTranslations`. Lumi's own text is exported as `translations`. No aliases remain.
- A page carries its own translations. A Spec may have a top-level `translations`, `{ locale: { key: text } }` (flat or nested keys), validated with the document. `LumiSpecPage` renders such a page under `withPageTranslations(provider, translations)`: `$t` reads the page's text for the active locale first, then the shared translations and Lumi's own (active, then fallback locale), then the page's fallback-locale text, then the default. It applies to that page only, so pages, drawer pages and included pages each keep their own, and switching the locale needs no reload. `I18nProvider` gains optional `getFallbackLocale()`, which `createI18nProvider` and `extendI18nProvider` supply. `pageTranslationsSchema` and `withPageTranslations` are exported from the root and `/catalog`.
- `LumiSpecPage` takes `initialState`: top-level entries set over the Spec's own `state` when the page mounts, so one cached document serves callers that each hand it their own values (a drawer's record, for example).
- Request hooks for signing and tamper checks. `createHttpClient`, `http.extend` and `createSimpleDataProvider` take `onRequest(request)` and `onResponse(response, request)`. `onRequest` sees the request as it leaves — absolute URL with its query, final headers after the auth's credentials, locale and tenant, and the encoded body (a JSON string, or FormData for an upload) — and may change it in place or return another; it runs again for the resend after a 401 refresh. `onResponse` sees the final answer whatever its status, may replace it, and fails the request by throwing. `extend` inherits both unless it names them. XHR uploads go through the same hooks: `HttpClient.authorize` is replaced by `prepare(request)`, which applies credentials and `onRequest`, and `receive(response, request)`, which applies `onResponse`.
- Permission strings in the backend's own shape. `createSimpleAuthProvider({ permission: { separator, format } })` builds the string a `{ resource, action }` check looks for: `system/users` + `delete` is `system:users:delete` by default (each `/` of the resource becomes the separator), `system.users.delete` with `separator: '.'`, and `format` reorders it, e.g. `{action}{separator}{resource}`. Every granted segment may be `*` and a trailing `*` covers everything below, so `system:*`, `*:users:delete`, `*` and the existing `orders:*` and `*:*` all work. A nested resource's permission is now `shop:orders:delete` rather than `shop/orders:delete`. `createPermissionMatcher` exposes the same rule for custom access providers.
- A resource has one name: `/shop/orders`, `shop/orders/` and `shop/orders` reach the DataProvider, the query cache, refreshes after writes, live channels and permission checks as `shop/orders`. `normalizeResource` is exported from the root and `/catalog`.
- Each backend's error format is read where its data is: `createSimpleDataProvider({ parseError })`, beside `unwrap`, turns a failed answer's body into `{ message, code?, data?, errors?: [{ path, message }] }`, and `createHttpClient` / `http.extend` take the same `parseError`. Everything downstream keeps one shape: `DataProviderError` with `status`, `message`, `code`, `errors` and the original `raw` body, so field errors still reach forms and the auth provider's `onError` only decides what a failure means for the session. `parseLumiError` is the default and exported, with the `HttpErrorDetails` and `HttpFieldError` types.
- One request path, with the credentials owned by the auth provider. `createHttpClient` (in `@duxweb/lumi`) sends every request: it asks the `AuthProvider` for the request's credentials through the new optional `authorizeRequest({ url, method })`, which returns headers and/or fetch `credentials`, so a bearer token, an API key, a signature or a cookie session with a CSRF header are all written once, in the provider that keeps them. It adds `Accept-Language` and the tenant header, encodes JSON, and on a 401 calls the provider's new optional `refresh()` once (shared by concurrent requests) before sending again; a non-2xx answer becomes a `DataProviderError`. Headers a request names itself never override the auth's. `http.extend({ baseUrl, auth: false, headers })` reaches another backend without the app's credentials, and a 401 from such a client does not sign the reader out.

  `createSimpleDataProvider` takes `http` instead of `getToken`, `tokenHeader`, `getLocale`, `getTenant` and `fetcher`, and exposes it as `DataProvider.http`; uploads, the agent and `createSseLiveProvider({ http })` sign through the same client, so `upload.headers` and `agent.headers` are only for extra headers and `agent.credentials` is gone. `createLumi` takes and exposes `http` (built from `authProvider`, `i18nProvider` and `tenantProvider` when not given). `createSimpleAuthProvider` runs its own sign-in requests through an HttpClient (`http` option) and gains `mode: 'cookie'` with `csrf: { cookie, header }`, and `endpoints.refresh`; `SimpleAuth.getToken` is removed. `dataProviderAuth`, `withSourceAuth` and `DataProviderAuth` are removed.

  In Admin, an `auth` entry takes `mode`, `csrf` and `endpoints.refresh`, and each `data` entry takes `auth: false`. Extension options are flat: `authProviders`, `accessProviders`, `i18nProvider`, `tenantProvider`, `liveProvider`, `auditLogProvider`, `toastProvider`, `notificationProvider`, `validator`, `upload`, `agent` and `env` sit beside `dataProviders` instead of under `providers`, and a module's `dataProviders.default` replaces the panel's provider. Extension module functions receive `{ config, panel, http }`, `http` being the app's signed client at the panel's backend. `getToken` is removed from the extension options and from `MountedAdmin`, which exposes `http`. The demo mock answers cookie sessions as well.

- Account pages beyond sign-in. `AuthProvider` gains optional `register`, `forgotPassword` and `updatePassword`, with the `useRegister`, `useForgotPassword` and `useUpdatePassword` hooks; registering goes through the same session queue as `login`, so a provider that signs the new account in resets cached session data the same way. `createSimpleAuthProvider` offers each one only when its endpoint is set (`endpoints.register`, `forgotPassword`, `updatePassword`), and the base config takes them under an `auth` entry's `endpoints`.

  Admin adds `/register`, `/forgot-password` and `/reset-password` for an auth provider that implements the matching method, as `LumiAdminRegister`, `LumiAdminForgotPassword` and `LumiAdminResetPassword`. Sign-in links to them: "Create an account" (hidden with `login.register: false`) and "Forgot password?" opening the reset page instead of the administrator toast. The reset request never says whether an address has an account, and a reset link without its token asks for a new one.

  All four share `LumiAuthLayout`: the brand and display tools along the top with an optional help link, and beside the card the host's own copy: an optional badge, a headline with a phrase drawn in the brand colour, a description and a list of points (icon, title, one line), over a thin wash of the brand colour. New `login` options: `badge`, `heroHighlight`, `help`, `register` and `assignedNote`. The sign-in page's class names move from `lumi-login__*` to `lumi-auth__*`.

- Data layer: tenants, live updates, mutation modes, permissions in JSON, URL-synced lists, import/export, document titles and an audit log.

  - **Tenants.** `createTenantProvider({ initial, options, storageKey })` and `LumiConfig.tenantProvider`; `useTenant()` reads and switches it. A switch resets every Lumi query in the same frame, so nothing from the previous tenant stays on screen. `createSimpleDataProvider` sends it as `X-Tenant` (`getTenant`, `tenantHeader`). In Admin the sidebar workspace is the tenant: `mountAdmin` stores it per app and adds the header to data, upload and agent requests.
  - **Live updates.** `LiveProvider` (`subscribe`, `publish`) and `createSseLiveProvider({ url, headers })`: one fetch-based SSE stream that carries the request headers and reconnects with backoff. Events on `resources/{resource}` refetch the lists and the records they name (`liveMode`: `auto`, `manual` or `off`, also on the JSON `Query`). `useSubscription` and `usePublish` cover other channels. In Admin, a `data` entry's `live` turns it on, and the stream reopens when the tenant changes.
  - **Mutation modes.** `mutationMode` on update and delete, for hooks, the JSON `update` and `delete` actions, and `LumiConfig.mutationMode`. `optimistic` changes cached lists, pages and records at once and rolls them back on failure. `undoable` also waits `undoableTimeout` with an Undo notice before sending. Forms always wait for the server.
  - **CanAccess.** `<LumiCanAccess resource action fallback>` and the JSON `CanAccess` element, which has a `fallback` slot and writes `{ can, loading, reason }` to `resultPath` so other elements can bind `disabled` or `visible` to it.
  - **URL-synced lists.** `useTable({ syncWithLocation })` and the Admin `ListPage` prop keep page, page size and sort in the query (`page`, `pageSize`, `sort=field:asc`). Reloads, shared links and back/forward restore them, and a string value prefixes the parameter names.
  - **Import and export.**
    - `useExport` and the `exportList` action download every record that matches the filters, page by page, as CSV or JSON. The CSV is UTF-8 with a BOM so Excel opens it, and spreadsheet formulas are neutralized.
    - `useImport` and the `importList` action read a CSV or JSON file. Headers are mapped by field or label, with `number` and `boolean` columns. Records are created one at a time, or in `createMany` batches when `batchSize` is set. Refused rows are skipped, progress goes to `progressPath`, and the result is reported in a notice.
    - The CSV and file logic is shared in core (`toCsv`, `parseCsv`, `readRecords`, `runExport`, `runImport`). The browser's save and pick steps come from `browserTransferHost`.
  - **Document title.** The Admin shell sets the browser title to `{page} · {app}` from the route's label. `app.documentTitle` changes the template, or turns it off with `false`. `useDocumentTitle()` lets a page name its record. Sign-in pages show the app title alone.
  - **Audit log.** An optional `AuditLogProvider` (`create`, `get`, `update`) records every accepted write from hooks and JSON actions, and each import as one event with its counts. Writes that are refused or undone are not recorded, and a log that fails does not fail the write. `createDataAuditLogProvider` keeps the log as a DataProvider resource. `useAuditLogList` reads it and refreshes after writes. In Admin, `AuditLog` / `LumiAuditLog` shows a resource's or record's history as an activity feed, and a panel's `auditLog` turns it on.
  - **Data providers.** One app can use several backends, each a `DataProvider` named in `dataProvider: { default, ... }`; an adapter for another API (Strapi, a legacy envelope) is just another `DataProvider`. `LumiDataProviderScope` sets the provider for a part of the app, and an Admin manifest route's `dataProvider` applies to it and every route below it; hooks, Query and data actions use it unless they name a provider with `dataProviderName`, and each provider keeps its own cache. A backend the app does not sign for is a client with `auth: false`, whose 401 does not sign the reader out. In Admin, a `data` list gives more createSimpleDataProvider addresses by name, and modules register their own providers with `dataProviders`.
  - **Extensions.** The manifest's `app.assistant` describes the Shell assistant (endpoint, @ tabs with their DataProvider sources, / commands, suggestions), and modules add `assistantCommands` and `assistantMentions`. Every module's `onEvent` and `onWorkspaceChange` runs, in order; a command without a prompt reaches them as `assistant.command`. `useAssistantContext` and the JSON `AssistantContext` element offer page context (such as the selected rows) to the assistant as removable chips.
  - Prebuilt base: `window.LumiAdminSetup` takes one extension or an array, and `LumiAdmin.use(extension)` adds more from scripts after the base; all merge before mount in order (config modules, setup, use). An extension may also replace the tenant, live and audit-log providers, and the request headers, sources and event stream follow a replaced tenant provider.

Issues keep their `{ path, code, params, message }` shape, and `{field}` (the path) is still available to host message overrides.
