# @duxweb/lumi-ui

## 0.1.0

### Minor Changes

- The root no longer exports `Badge`, the internal primitive that had slipped through beside `LumiBadge`.
- IconPicker shows no icons when its icon set fails to load, instead of loading forever; a Repeater column's `precision` outside 0–20 no longer fails the render.
- Cascader, CascaderPanel, Tree, TreeSelect, Repeater columns, ColorSwatches and Lightbox render empty when their list is `null`, as it is while a bound Query loads, instead of failing. A Tree node whose children fail to load closes without closing nodes opened meanwhile.
- RichText takes `checks` like the other fields; a Checkbox or Switch without a label applies its `className`.
- DateTimePicker keeps the picked time inside `min` and `max` on the first and last allowed day, and gives back an instant in UTC when its value was written with an offset (`…Z`), instead of local time without one. Date pickers read the day a value names, so a UTC timestamp no longer shows the day before west of UTC. DatePicker, TimePicker and DateTimePicker accept `null` as an empty value.
- A Slider's number box can be typed into: a value on its way through the range waits until it is inside it, or until the box is left or Enter is pressed. A slider whose `min` has decimals keeps them.
- Table rows that lack their `rowKey` are no longer selected or highlighted under their position on the page, which named another row after a page change or a sort; they cannot be selected.
- Select and MultiSelect emit `loadMore` when the list is scrolled to its end with `hasMore` set, so a plain page can append the next options. A control's native `aria-label` in a Spec names it like `ariaLabel`.
- Retrying a failed upload is refused when its slot has since gone to another file, instead of exceeding `maxFiles`.
- A `null` value in state (a cleared field, a reset form, a backend field that is JSON null) reads as empty: Cascader, MultiSelect, CheckboxGroup, TagsInput and DateRangePicker no longer fail the render (clearing a bound Cascader did), and Input, Textarea and RichText empty instead of keeping the old text.
- Dialog treats every way out but the confirm button as a cancel (Escape, the close icon, a click outside now emit `cancel` too), writes `open` before emitting it, and stays open while `loading`.
- Pagination steps back to the last page when the current one is past the end, and never offers an `Infinity` or `NaN` page for a `pageSize` of 0.
- A Table currency column or a Chart with a currency or locale code `Intl` does not know shows the plain number instead of failing the render; a Chart whose bound `points` have not loaded shows its empty state.
- TimePicker (and the time columns) keep a picked time inside `min` and `max`; NumberInput steps keep the decimals already there (1.5 + 1 is 2.5); a multiple TagSelect keeps chosen values that are not among its options.
- Upload: in single mode a refused file no longer aborts the upload in progress; an abort that came from the transport shows as a failure that can be retried instead of a row stuck uploading; ImageGrid releases its local preview URLs.
- `Upload` and `ImageGrid` document `upload.sign` for direct-to-storage uploads (see `/lumi`).
- `Iframe` shows another web page: `src` (https or a path on this site; other schemes render a notice), `title`, `height` (px or `fill`, 480 by default) or `aspectRatio`, `sandbox` (on by default: scripts, forms, popups, downloads) and `allowFullscreen`. Frames are lazy and send the origin as referrer. `LumiEmbedProvider` limits the sites frames below it may show; `embeddableUrl(src, origins)` applies the same rule.
- Table rows carry their own buttons. `Table`, Admin `DataGrid` and `ListPage` take a `rowActions` slot: its elements (plain `Button`, `Popconfirm`, …) are drawn in every row of the `kind: "actions"` column, each with its own `on`, so Edit can `setState` a dialog open while Delete runs `delete` behind a confirmation. Props read the row through native `$item` and `$index`; before a control's action runs the row is written to the bound `activeRow`, so params read it with `{ "$state": "/table/row/id" }` (native `$item` in action params is a state path, not a value). A click on a control does not also fire `rowClick`. Without the slot, the column's `actions` menu and `rowAction` work as before. React hosts pass `renderRowActions(row, index)` to `LumiTable`; `rowActionsRenderer` builds it from slot children inside a native repeat scope.
- Lumi UI adds the `ActivityFeed` component: an avatar, one sentence with the actor and target in strong text, a context line with an optional status badge, and the time at the end of the first line; a phrase can place `{actor}` and `{target}` for languages with another word order. `Timeline` puts the time at the end of the title's line by default (`datePlacement: "below"` stacks it), centres its markers on the title line, threads one continuous rule through them, and draws current as a brand ring on a halo and upcoming as a hollow ring. Lumi Admin adds `valueTone: "muted"` to `ProportionList` for a secondary count, and the detail page timeline keeps the time under the title. Lumi ships English and Chinese text for the feed's empty and loading states.
- New agent UI components in `@duxweb/lumi-ui`, each with a Catalog definition and native Registry binding so JSON Specs (including model-written ones) can use them: `PromptInput` (auto-growing message box with attachment and @-context chips, a compact model picker, prompt starters, Enter to send, Shift+Enter for a new line, and a stop button while `streaming`), `ChatMessage` and `MessageActions` (Markdown answers with a streaming caret, citation chips that preview their source on hover or focus, copy, regenerate, thumbs up/down and follow-up suggestions), `Thinking` (a working pill with phase and elapsed time that settles to a check with the time taken, plus foldable steps), `ToolCall` (status, duration and JSON input/output in `CodeBlock`), `Approval` (human-in-the-loop confirmation before a registered action, with a narrowable item list, risk tone and approved/rejected/expired states), `AgentPlan`, `ChangeDiff` (record field changes, or a line diff of two texts in the `CodeBlock` style), `ContextChips` (viewed page with a share switch, removable context items and a usage meter) and `ChatThread`, which renders an array of messages. Interactions go through bound state and events: bound `messages` keep ratings and approval decisions, and `activeEvent` receives `{ type, messageId, partId?, value? }` before each event. The spinner is the only motion; the caret stops for readers who prefer reduced motion.

  The components share one documented message contract, exported framework-free from `@duxweb/lumi-ui/catalog` (`agentMessageSchema`, `agentMessagePartSchema` and a schema per part): `{ id, role, parts, status? }` with `text`, `reasoning`, `tool-call`, `approval`, `plan`, `diff`, `source`, `file` and `context` parts. Names follow the Vercel AI SDK `UIMessage` where they mean the same thing, so backends convert with a small mapping. `LumiMarkdown` renders the safe Markdown subset the answers use: no raw HTML, and only http(s), mailto, tel and relative links.

  `LumiAssistantPanel` is recomposed from these components. `LumiAssistantMessage` is now the message contract (`parts`, `status`, `feedback`, `suggestions`) plus an optional host-rendered `content`; the `steps`, `citations` and `action` fields are replaced by `reasoning`, `source` and `approval` parts, with approval decisions, ratings, regenerate and source clicks passed through the new `thread` prop. New props: `streaming`/`onStop`, `models`/`onModelChange`, `references`/`onReferencesChange` and `attachments`/`onAttachmentsChange`; `onAttach` now receives `File[]`.

  Controls that sit in a line of text or a chip (inline citations, chip remove buttons) carry `data-hit-area`: the Admin touch rules leave their size alone and they reach the 44px target through their own hit area.

  Adds the `lumi.agent.*` messages in English and Chinese.

  Agent session service in `@duxweb/lumi`: `createAgentSession` streams replies in the AI SDK UI message stream format (SSE, `x-vercel-ai-ui-message-stream: v1`) and merges the chunks into agent messages — text, reasoning with its duration, tool calls, sources, files, suggestions and `data-approval` / `data-question` / `data-plan` / `data-diff` cards. With `resource` a conversation loads through the DataProvider and the resource refreshes after each reply. Admin passes its auth headers as `agent.headers`.

  Admin `AgentWorkspace`: a full-page conversation over one agent session — the conversations from the `agent-sessions` DataProvider resource, the streamed thread and the composer, with the open conversation in the `?session=` query parameter. In the dual layout the conversations take the shell's second column in place of the module menu; a page claims that column with the new `ShellContextPanel` (or `useShellContextPanel`) and falls back to drawing the content itself where the column is absent, collapsed or too narrow. A decision on an approval or question that arrives before its reply ends is kept and sent once the reply is done, and a thread that stops overflowing drops its jump-to-latest button.

  Admin `useAgentConversation` wraps one conversation and its list — the agent session, the debounced conversation search over the DataProvider, the draft, sending with context, opening and starting conversations — and returns props to spread onto ChatThread, PromptInput and AgentSessionList; the open conversation can be kept by the host (`sessionId` / `onSessionChange`) or by the hook. `AgentWorkspace` and the new `LumiAgentPanel`, the Shell assistant panel connected to an agent endpoint with the viewed page sent as context while shared, are both drawn from it. Agent chips and the secondary lines of selected sessions and highlighted mention options meet the 4.5:1 contrast ratio, as do toned alert titles, the counts of unselected TagSelect options, neutral chips inside dark tags inputs and input prefixes and suffixes. A toast's live role moves to its message, so the toast list holds only list items, and an enabled code editor's content is an explicit tab stop.

  `useHideShellAssistant()` lets a page that is itself a conversation hide the Shell's assistant panel and its toggle while mounted; `AgentWorkspace` uses it. The session list's "New chat" is a primary button, and compact rows show the time beside the title.

  Layout polish: mention options are taller with a framed icon tile that stays visible on the highlighted row; approval and question cards have a tighter head with the action line under the title, roomier item rows and options, and numbered keys distinct from multiple-choice checkboxes (`data-mode` on AgentQuestion); a purchase approval puts Reject beside a wider Pay under a larger total; timeline and plan rows are taller. The ChangeDiff gutter draws old and new line numbers in two equal columns on a quiet band with a hairline before a centred sign column, tints changed rows' numbers, and folded unchanged lines read as one bordered row.

  PromptInput gains @ references and slash commands. With `mentions` (`types`, static `options`, `placeholder`), an @ typed at the start of a word or the @ button opens the reference picker over the box; a pick becomes a `context` chip in place of the typed @, and Escape keeps the @ as text. With `commands` (`value`, `label`, `description`, `icon`, `prompt`), a box holding only `/` and part of a name lists them; arrow keys, Enter or Tab pick, Escape closes; a command with a `prompt` fills the box, others write `command` and emit `command`. `connectPromptInput(mentionPicker)` builds the registry body with a host's picker. In Admin, PromptInput `mentions.sources` searches one DataProvider resource per tab, and `useAgentConversation`, `AgentWorkspace` and `LumiAgentPanel` take `mentions` and `commands`: picks go with the next message as context and clear once it is accepted, and a command without a `prompt` reaches `onCommand` or is sent as its label.

  Thinking and activity headers are a compact pill of status and time, the current phase or summary moving to its tooltip. Approval no longer shows its `action` name to the reader; it identifies the decision for the host only.

  Agent bridge: the agent sees the running front end and does light work on it, filling and pointing, with nothing declared per component; business writes belong to backend tools. `LumiSpecPage` registers the page it renders with `lumi.agentBridge` (`agent={false}` opts out): its elements with `$bindState` props, `statePath`, `href` or `on` events, their labels, resources and fields, and the page state; events split into light `events` (only actions in `agent.safeActions`, no `confirm`) and `writes`. The Admin Shell registers the current route, the menu routes and how to open them. `useAgentChat` sends this snapshot as `ui` with every request, with `clientTools` and `approvalMode`. The client tools: `ui_navigate` opens a route and waits for its page, failing when the move is held by an unsaved-changes prompt; `ui_set_state` writes a bound path or below; `ui_trigger` fires light events only and refuses writes. A call answering a page the reader has left is refused, and values the reader changed since the snapshot, or the form field they are typing in, are kept and reported as `kept`. The session runs client tool calls a reply leaves open and goes on with trigger `tool-output`; a client tool may ask first with `approval` in `ask` mode, which the bridge tools never do. The approval mode is for backend tools: PromptInput `approvalMode` shows the permission switch ("Ask every time" / "Full access"), `useAgentApprovalMode()` reads and sets it, and it is kept in local storage.

  A notice's live role moves from its list item to its body, so the notifier list holds only list items, as the toast list already does.

  Table selections and highlights for the agent. `LumiSelectionExtras` adds commands to the selection bars of every table below it (read with `useSelectionExtras`); a table, DataGrid or ListPage shows its bar for them even without bulk actions, and each command gets the selected keys with the loaded row of each. The Admin Shell adds "Reference in chat" while an assistant panel is there: the rows become `record` context chips whose new `data` field carries their fields to the agent, and the panel opens (`bridge.reference` / `bridge.onReference`, kept until a conversation listens). A fourth client tool, `ui_highlight`, points at things: with `keys` Lumi dispatches the `lumi:highlight` window event (`LUMI_HIGHLIGHT_EVENT` in Lumi UI) and every table marks the matching rows with an accent bar, scrolls to the first and lets the mark fade after four seconds; with `element` the visible button, link or tab of that label flashes (`data-agent-flash`, a pulsing accent ring) outside elements marked `data-agent-surface`, such as the assistant panel. The UI snapshot carries the current Admin workspace read only; the agent never switches it.
