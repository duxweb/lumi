# Lumi 示例菜单与完整性评估

## 对照依据

核对日期：2026-09-21。使用 Context7 查询官方项目，并阅读官方当前页面；比较信息架构与覆盖范围，Lumi 继续使用自己的组件和视觉规范。

- [Ant Design 组件总览](https://ant.design/components/overview/)：按通用、布局、导航、数据录入、数据展示、反馈等类别组织组件入口。
- [Ant Design Pro 当前模板清单](https://github.com/ant-design/ant-design-pro/blob/master/README.md#templates)：仪表盘、基础/分步/高级表单、查询/基础/卡片/搜索列表、基础/高级详情、结果、异常、账户、登录注册及 AI 助手。
- [Tabler 官方演示](https://preview.tabler.io/)：独立的组件、表单、图表、布局和认证页面入口，另有业务附加页。数量不作为 Lumi 验收标准。

## 原菜单问题

1. 业务名称和页面模式混排：New Product、Write article、New project 隐藏了分步、发布、页签表单的区别。
2. 没有总览和搜索入口，详情与抽屉需先知道业务路径才能发现。
3. Everything (25 + 4) 是开发时期计数，不是用户可理解的分类，也没有告诉用户每个组件在哪里。
4. 组件页仍使用 Frame 包 Card 的旧布局；小标题、层层边框、纵向铺满控件，与新页面规范不一致。
5. Gallery 中 Dialog/Drawer 为关闭状态且没有触发器，Tabs 没有切换内容；存在“定义里出现过就算覆盖”的问题。
6. 基础表单、账户中心、订单列表、状态恢复和原生服务联动缺少可发现的独立示例。

## 本轮落地

| 类别 | 示例入口与行为 |
| --- | --- |
| 总览 | `/examples`，按能力分组并可搜索的工作流目录 |
| 组件 | `/ui/standard` 改为组件总览，按名称/说明搜索并跳转具体区块 |
| 组件展示 | 六个分类页统一标题、独立示例卡片、响应式控件排列、区块导航、重置、可展开的实际 native Spec |
| 列表 | 查询表格、基础列表、卡片、搜索、订单；`/examples/lists` 汇总入口 |
| 表单 | 新增 `/examples/forms/basic`，真实 mock 创建客户；原产品/文章/项目表单按 Step / Publishing / Tabbed 分类 |
| 详情与覆盖层 | `/examples/details` 提供基础/高级详情、抽屉表单、抽屉表格和模态表单的直接入口 |
| 账户 | 新增 `/account/center`，读取账户资料与活动；保留完整四类设置 |
| 图表 | 新增 `/ui/charts`，展示已支持的 area / line / bar / donut、数据表与空数据切换 |
| 状态 | `/examples/states` 可操作切换并恢复 loading / empty / error / offline / timeout / permission |
| 原生集成 | `/examples/native`：原生绑定、动作、条件显示、Query 挂载加载、筛选变化请求、invalidate 刷新 |
| 业务闭环 | 新增 `/orders`，筛选、排序、分页并进入已有订单详情 |

菜单保留业务空间 Catalog / Content / System / Workspace；Examples 按表单、页面模式、状态和集成组织。Overview 提供全局目录，Components 提供组件目录。现有路由地址继续可用。

## 相比同类仍缺的产品能力

下面是 **Lumi 尚未公开提供的能力或尚未实现的独立产品流程**，不能用一个静态页面冒充完整实现。

| 优先级 | 缺口 | 当前边界与后续验收 |
| --- | --- | --- |
| P1 | Tree / TreeSelect / Cascader / Transfer | UI Catalog 未提供；需要节点选择、搜索、展开、懒加载、键盘和 JSON 绑定一起交付 |
| P1 | 独立反馈与导航组件 | Shell 内已有菜单与提示等能力，公开 UI Catalog 尚未形成 Tooltip / Popover / Dropdown / Toast / Progress 等完整示例分类；需先明确公开 API |
| P1 | 登录之外的认证流程 | 已有真实 mock 登录、退出、角色和路由访问；注册、重置密码、MFA 和绑定账号尚无完整服务契约 |
| P2 | 更多数据录入组件 | Slider、Rate、TimePicker、ColorPicker 等需组件、Catalog、Registry、JSX/JSON 对等和完整交互测试 |
| P2 | 监控面板与高级业务模板 | 实时监控、任务看板、日历、文件管理、聊天和 AI 助手目前没有对应完整数据/交互服务 |
| P2 | 全局偏好应用 | 设置示例保存偏好，但语言、日期和工作区偏好应用到整个宿主的策略仍由实际应用接入 |

本轮完整性的边界是：**现有 Lumi 能力可发现、可操作、可查看源 Spec、具有成功和恢复路径**。这不等于 Ant Design 全部组件和 Ant Design Pro 全部业务模板已经实现。新增上述能力属于后续产品扩展，不在菜单中挂空入口。

## 验收要求

- 示例目录内链接必须解析到实际路由，包括动态详情和带查询参数的抽屉。
- Gallery 与原生联动 Spec 使用运行时相同的 Catalog 校验，不维护私有 schema 表。
- 验证输入重置、对话框/抽屉打开关闭、页签内容切换、基础表单创建、订单详情导航、原生筛选请求和刷新。
- 所有组件分类在桌面/手机进行 axe 与页面宽度检查；主要页面在三种尺寸、明暗主题下保存原创截图。
- 发现的公共 UI 对比度问题修在 UI 样式层，不在示例里绕过检查。

## 本轮验证结果

- 根 typecheck、lint 与 308 项单测通过；后续账号中心改用 `/me`，其类型检查与相关 6 项单测复测通过。
- 根 build 通过，包含文档代码、Schema、类型示例和产物链接检查。首次与类型检查并发构建时声明生成失败；串行重新构建通过。
- 根 E2E：42 项通过，1 项因旧测试仍从表单侧栏寻找 Products 菜单而失败；菜单改为 Examples 后，测试改走 Catalog 模块并保留全部 dirty guard 断言，复测通过。
- 新增经理账号中心用例，确认无需用户管理权限即可读取自己的资料。最终新增账号用例、基础表单工作流和原回归用例三项复测通过，合计覆盖 44 个浏览器用例。
- 四种桌面/手机明暗组合覆盖全部组件分类及新增示例的 axe 与溢出检查。
- 新增组件文本、覆盖层、组件目录、工作流目录的 24 张截图；更新 7 张现有基线。126 张原创截图清单验证通过。
- Schema checker、生成文档一致性和包体积检查通过。
